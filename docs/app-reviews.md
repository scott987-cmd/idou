# 企业应用清单审核

入口在「编程任务」首页及任务内「应用版本」，不新增一级导航。流程：作者保存不可变清单 → 企业审核人查看清单 → 原生确认通过/退回及说明 → 作者刷新看到结果。审核人不需要在本机创建作者的任务。

## 审核范围

这是**清单级流程审核**，不是源码安全审查、发布许可或已部署服务。审核人查看标题、应用 ID、完整版本哈希、提交时间、静态运行/网络声明，以及每个文件的路径、大小、哈希。界面不下载/执行源码，不把网络声明当作静态扫描证明；审核接口不返回作者的云盘目录、file token、上传凭据或归档字节。通过后仍显示「清单通过 · 未部署」，并且不会生成访问地址、调用模型、触发上传、赋予飞书权限或执行构建。

审核人与作者均可看到审核说明和时间。说明仅是受限长度文本，不作为 Agent 指令或 HTML 执行。撤回版本仍保留历史结论，但撤回状态优先；批准不能恢复撤回状态。修改源码后是独立的新版本，不能继承旧结论；现阶段不允许覆盖结论或为相同清单重新申请，意见修正/多级会签/撤销审批仍需后续策略。

## 服务端配置与迁移

在既有 `IDOU_APPS_CONFIG_FILE` 的对应 tenant 条目中增加可选 `reviewers` 数组：

```json
{
  "authProvider": "feishu",
  "tenantId": "your_verified_tenant_key",
  "appId": "cli_your_product_app",
  "publishers": ["author_product_user_open_id"],
  "reviewers": ["reviewer_product_user_open_id"]
}
```

标识均来自**本产品 OAuth 应用**验证的用户身份，不能使用另一个飞书应用的 `open_id`，也不能用客户端声明的人名/部门授权。省略 `reviewers` 默认无人可审核；拒绝通配符、重复项和无效类型，每租户最多 1000 人。审核人可查看该身份域内其他作者的所有候选清单（包括按精确 ID 读取已处理/撤回历史），不是仅某个部门的审批人；管理员应在启用前确认此元数据可见范围。配置在服务启动时加载，部署修改需受控重启。撤去角色后每次请求重新授权，不把已签发的短期 token 当作角色豁免。

数据库增加 `application_reviews`，以租户身份域 + 应用 ID + 版本哈希为唯一键。保存审核人身份哈希、结论、说明、时间和记录 ID，不保存源码。启动时在事务中把版本 1/2 增量升级到 **user_version=3**，保留候选和归档；不支持老二进制直接打开版本 3。生产升级前需一致备份数据库与 WAL；自动回滚、集群故障切换和生产迁移尚未验收。测试只迁移临时合成数据库，没有改动客户部署。

## 授权、竞争与结果未知

- 独立 `app-review` audience / `apps:review` scope，由 `/auth/app-review-token` 使用有效模型父会话兑换；最长 5 分钟且不超过父会话。模型、归档、媒体和目录 token 不能代替审核 token；审核 token 也不能提交/撤回版本或调用模型。父会话撤销使派生 token 失效。
- 请求按认证来源、租户、产品 App ID、当前审核人名单验证；服务端拒绝作者自审。不能靠同名应用、换 device ID 或另一个产品 App 的用户标识绕过。每个版本的首个结论在 SQLite `BEGIN IMMEDIATE` 事务内写入；完全相同审核人的相同结论/说明重放返回原记录，其他结论返回冲突，不覆盖历史。
- 原生客户端把审核清单绑定到当前会话和短期 handle。确认前以及原生确认后重新读取清单/状态/授权；关闭页面、切换账号、过期、他人先审核或作者先撤回均拒绝未发送的提交。最后取得短期 token 后还检查页面代次。请求已发出之后，关闭界面不能撤销已落库结果，须读取核查。
- 原生确认默认取消。客户端在写请求前消耗确认，不自动重新提交；响应丢失提示「重新读取此版本」核查。服务端幂等是防重复落库，不是自动重试授权。客户端状态不是部署授权源。
- 队列每页最多 10 项，仅列其他作者尚未处理且未撤回的清单，使用 `(appId,digest)` 游标。它是实时队列而非固定快照；并发新提交可能出现在前页，刷新首页重新发现。已处理历史通过已知版本读取，不提供无限历史列表。

## 验证与未完成项

`test/app-review.test.js` 覆盖实际本机源文件/HTTP/SQLite/原生客户端，含角色与 audience 隔离、作者自审拒绝、父会话撤销、确认竞态、结果丢失的只读恢复、完整清单哈希、分页与版本 2 迁移。四个独立 Node 进程竞争同一版本，只有一个首次结论成功。隔离进程删除作者自审守卫后测试失败（200 而非 404）；生产代码未为变异改写。

`node scripts/smoke-app-review-desktop.js` 使用实际 Electron 窗口和本机 HTTP/SQLite，合成两个用户会话：作者提交 → 审核人无本地任务读取 → 取消零提交 → 原生确认 → 回读不可覆盖结论 → 作者重启看到结果 → 新版本不继承 → 确认期间撤回阻止提交。截图 `evidence/desktop-app-review-fixture.png`、`desktop-app-review-narrow-fixture.png`、`desktop-app-review-author-fixture.png` 已打开检查。没有真实飞书调用或模型费用。
