# 文档网站阶段 0：把承诺做实

[site-benchmark.md](site-benchmark.md) §3 列出的问题，逐条怎么修、怎么证明修好了。每一条都要有一个撤掉修复就失败的测试；涉及浏览器行为的，用真的浏览器（Playwright 的 Chromium）打开真的已发布页面验证，不再用 `fetch` 代替页面。

## 0.1 表格数据真的跟着表格走

**现在**：页面运行时（`table-contract.js`）只在 `schema.endpoint`、`schema.stream` 设了时才取新数据和听变更；发布时没人设它们，访客看到的是发布那一刻 `data/table-data.js` 里的快照。

**改成**：服务端提供已发布网站的 `data/table-data.js` 时，不再给版本里那份文件，而是按当前数据现生成：`window.__IDOU_TABLE__ = { schema: {...，endpoint, stream}, snapshot }`。`endpoint`、`stream` 是这个访客这次能用的绝对路径（带 §0.2 的令牌）。于是：

- 刷新页面拿到的是最新一份（不是发布时那份）；
- 页面开着时，表格一变（桌面或服务端刷新写进 `/v1/sites/data`），服务端推 `changed`，页面取 `_data` 重画；
- 没有数据源的网站，`data/table-data.js` 照版本里的给。
- 每个开着的表格网站占一条变更通知的长连接。浏览器对同一地址的 HTTP/1.1 连接最多 6 条，所以不加 TLS 的部署，同一个浏览器同时开 6 个以上网站会排队；生产用 nginx 的 HTTP/2，没有这个限制。部署网站要用 https（免登录公开本来就要求 https）。

## 0.2 网站彼此隔离

**威胁**：同一租户里的发布人写一段脚本，读访客能看的别的网站（页面、脚本、数据），再用跳转带出去。

**两种做法，都做**（用户 10-03 决定）：

1. **每个网站一个源**（部署方配了泛域名时）：`https://<编号>.<网站域名>/`，cookie 只属于这个网站的域名；登录走公共域名，回来时用一次性票据在网站自己的域名上种 cookie。这种模式下浏览器的同源策略本身就隔离了网站。
2. **兜底：沙箱页面 + 路径令牌**（一个域名下的 `/s/<编号>/`）：
   - 访客打开 `/s/<编号>/…`，照旧用登录 cookie 认人、判权限；允许时重定向到 `/s/<编号>/~<令牌>/…`。令牌由服务端签发，绑定网站、访客、过期时间（和登录一样 12 小时）。
   - 网页文档带 `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads`：页面是一个不透明的源，读不到任何别的页面、窗口、框架，跨源请求也读不到回应。
   - 页面自己的资源、数据、变更通知都在令牌路径下，靠令牌认（沙箱页面发出的请求不带登录 cookie）。别的网站拿不到这个令牌：它在这个网站的地址里，而那个地址别的网站读不到。
   - 打开网页（导航）时既要令牌也要登录 cookie 对得上，复制给别人的带令牌地址对别人没用：别人打开会被送回 `/s/<编号>/…` 的正常入口。地址栏里保留令牌（想过注入脚本换回干净地址，但要配合 `<base>`，会弄坏页面内的 `#锚点` 链接，没有做）。
   - 只有浏览器声明「这是页面在取资源」（Fetch Metadata：`Sec-Fetch-Dest` 是 script、style、image、empty 等）时，令牌本身才够；什么都不声明的请求（curl、聊天软件的链接预览）一律按打开网页处理，要登录对得上。
   - 令牌加密（AES-GCM，绑定网站），页面脚本读自己的地址时看不到访客是谁。
   - 令牌路径下的每一个响应都带沙箱指令，不只是 HTML：SVG 也是文档，单独打开或被页面用 `window.open` 打开时同样不能以服务器的身份运行。
   - 数据接口和变更通知对沙箱页面回 `Access-Control-Allow-Origin: null`；它们只认令牌，所以这不放宽任何东西。
   - 作者在页面里写绝对路径 `/s/<编号>/x.js` 会绕过令牌而加载失败；发布时检查并拒绝这种写法（模板都是相对路径）。

**证明**：浏览器里打开网站 A（脚本恶意），访客同时能看网站 B：A 的脚本 `fetch` B 的数据、`<script>` 引 B 的数据文件、`window.open`/`iframe` B 再读它的内容、读 B 的令牌——全部失败；A 自己的数据照常加载、照常实时更新。

## 0.3 访客的飞书令牌过期就重新登录

**现在**：跟随表格权限要用访客自己的飞书令牌问飞书；令牌只在内存，过期（约 2 小时）或服务端重启后，访客被告知「没有表格权限」。

**改成**：令牌没有或过期时，这个访客等于没登录过这个问题，走一次登录（飞书已登录时是一来一回的自动跳转），不当成拒绝。令牌存进共享状态（加密，带过期），重启不丢；服务端多副本时也一样。飞书明确回答「没有权限」（`auth_result: false`）才是拒绝。

## 0.4 邀请人、部门、群

**现在**：服务端支持按人、群、部门放行，桌面从来没发过；群和部门的成员关系服务端也没接上。

**改成**：
- 桌面发布对话框「仅邀请的人」下面加「添加协作者」：搜飞书通讯录的人、搜群（自己在的）、选部门，显示为可删的标签，最多 200 个。用本人的飞书身份搜。
- 服务端判「群」用应用机器人读群成员（和管理员群一样的缓存），判「部门」用组织架构（访客所在部门及其上级）。
- 改协作者照旧走发布的确认卡片和内容安全（受众变了）。

## 0.5 网站列表在服务端

**现在**：列表只在本机；换台电脑看不到；「移出列表」后网站还在线却没地方下线；彻底删除没有入口。

**改成**：
- 桌面打开文档网站时，向服务端要「我发布的网站」（已有 `/v1/sites/list`），和本机的合在一起：本机没有的显示为「在别的电脑上发布」，可以下线、改范围、看统计、删除；要改页面得在原电脑或「把网站下载到这台电脑」（取当前版本的文件，放进新的本机文件夹）。
- 「移出列表」拆成两个：「下线并删除」（确认卡片，服务端彻底删除，删除卡片按删除规则走）和「只在这台电脑隐藏」（网站照常在线，提示仍可在服务端列表找回）。

## 0.6 版本和回退

**现在**：保留 3 个版本，没有回退。

**改成**：服务端加 `/v1/sites/versions`（列出：版本号、发布时间、文件数、大小、哪个在线）和 `/v1/sites/rollback`（回到某个保留的版本：等于用那一版重新发布，过内容安全，记审计）。桌面网站行的「更多」里有「历史版本」，每一版可以预览、回到这一版。

## 0.7 发布进度和刷新失败

- 发布中，网站行上显示「正在上传 / 正在检查内容（公开网站要 AI 读一遍，最多几分钟）」，按钮置灰；结束后显示结果。
- 自动刷新失败：网站行标出「数据没有更新：原因 · 最近一次成功是 X 分钟前」；连续失败 3 次通知一次（系统通知）。
- 「应用开着时才自动读取」的限制留到阶段 2（服务端定时刷新）。

2026-10-08 还改了发布收哪些文件。一个完全访问的编程任务在只有文件的网站里做 three.js 小游戏，撞上三件事：

- **`vendor/` 不收**：以前它和 `node_modules` 一样不进版本，本机预览也不提供。任务按要求把 three.js 放进 `vendor/`，页面在预览和线上都加载不到，任务自己挪到了 `lib/`。`vendor/` 是页面自带库的惯常位置，现在照常发布、照常预览；不发布的只剩以 `.` 开头的名字和 `node_modules`，预览和版本按同一条规则（`manifest.js` 的 `appLeftOutName`）。页面、样式表或脚本引用了不发布的文件时，网站行上列出来（「index.html（用到的 node_modules/three/build/three.module.js 不会发布）」），发布也整版拒绝，不再上线一个缺文件的页面。
- **Markdown 拦住发布**：目录里有 README.md、PLAN.md，网站就发布不了（「不能发布这种文件」），任务只好把它们改成 .html，再把 .md 挪出目录。现在 Markdown 是关于网站的说明，留在目录里，不进版本，也不拦发布；服务端照旧不提供 .md（清单里不能有它）。页面链接到它时按上一条列出。
- **说明文件写进了 i豆 自己的数据**：编程任务只被告知「放到这个目录外面」，于是在完全访问下把计划、说明和一次 npm 安装写在了网站目录旁边，也就是 i豆 存放所有网站的目录里。完全访问没有沙箱能拦，只能靠说明：网站目录上的编程任务现在被告知 Markdown 可以留下、库放 `vendor/` 或 `lib/`、和网站无关的东西（下载、为了取一个文件装的包、草稿）放进自己用 `mktemp -d` 建的临时目录；i豆 自己建的网站目录，还写明上一层是 i豆 的数据、放着别的网站、什么都不能写。已经写进去的文件没有动。

证明：`test/app-candidates.test.js`（`vendor/` 进版本、预览恰好提供版本里有的文件；Markdown 留在目录、不进版本；引用不发布的文件被列出且拒绝，正文里提到、CSS 类名、不存在的文件都不算；列出的和拒绝的仍然一一对应）、`test/gateway-config.test.js`（说明文字，i豆 建的目录才说上一层是 i豆 的数据）、`scripts/smoke-site-rules-desktop.js`（真应用里网站行上的提示，和发给模型的说明）。每条都撤掉修复跑过一遍，确认会失败。

**部署顺序和回退**：清单里哪些路径合法，服务端和桌面用的是同一个函数（`manifest.js` 的 `appPath`）。所以服务端要先装这一版、桌面后装：旧服务端收到带 `vendor/` 的版本会整版拒绝，说「这个位置不会被发布：vendor/…」（在内容检查之后）。装上以后服务端再回退到更早的版本，已经发布的带 `vendor/` 的网站照常在线（取文件只查清单、不查路径规则），但那一版不能「回到这一版」，历史版本里预览不了，旧桌面也下载不到本机。

还没做的：

- 「下载到这台电脑」的表格网站，本机只改页面；读取表格仍在原来那台电脑上，要换电脑读取得在新电脑上重新接表格。服务端定时读取在阶段 2。
- 服务端已经删掉、本机还记着的网站，行上没有专门说明（发布会提示「服务端找不到这个网站」）。
- `smoke-sites-desktop.js` 卡片之后的部分（取消发布、换风格、移出列表改成从「⋯」进入）要有人在场用 `--with-person` 跑一次。

## 阶段 0 的审查（2026-10-03）

四个只读审查（安全、状态与数据、桌面流程、回退兼容）加上自己复核，找到并修了：

- **隔离被 SVG 绕过（高）**：只有 HTML 带沙箱，网站 A 的 SVG 被打开后以服务器身份读到了网站 B。现在令牌路径下全部带沙箱，`test/site-isolation.test.js` 用 Chromium 重现过。
- **复制出去的令牌地址对 curl、链接预览有效 12 小时**：改为必须由浏览器声明是子资源。
- **令牌里明文写着访客的 open_id**：改为加密。
- **飞书拒绝刚发的凭据时登录绕圈**、**飞书没回答时每个文件都问一遍**：已修。
- **读群成员失败被当成「没分享给你」并缓存 90 秒**：改为「暂时没能确认」（503），不缓存。
- **分享接口先问机器人、后查归属和格式**，缓存无上限：先校验、先查归属，群成员缓存有上限。
- **回退的几处细节**：回到当前版本前先跑了检查；并发冲突报 400；旧记录回退后时间写错；回退后已批准的版本又要审。都已修。
- **扩大谁能打开不弹卡片**：现在扩大时弹卡片，缩小不拦。
- **桌面端**：服务端已删的网站卡在列表里；服务端没回答时打开分享设置一保存就清空协作者；协作者句柄几分钟就失效；同名的人加不进来；读不到的表格每 15 秒重画整个列表；下载来的表格网站被当成「只有文件」；两次重画叠成两份列表；对话框关闭时把里面的确认卡片和卡片容器一起删掉。都已修。
- **兼容**：旧版桌面更新「下载来的表格网站」会清掉服务端的数据源，改为服务端保留；新版桌面接旧服务端时不再提供旧服务端不支持的「按群邀请」和「历史版本」，没有的接口说「服务端版本太旧」而不是「没开启文档网站」。

**部署时要决定的一件事（回退底线）**：带令牌的地址是这一版新增的地址形状，.271 不认识。上线后再回退到 .271，访客收藏或复制过的带令牌地址会 404（手动删掉地址里的 `~…/` 那一段就能打开）。按回退安全的规则，应当先发一版只认这种地址、不签发令牌，下一版再签发；但网站互相读取的漏洞在线上的 .271 已经存在。建议这一版直接上线隔离，把回退底线定为这一版，并在发布说明里写明。

审查时桌面冒烟没能全部重跑：屏幕锁定期间，应用在 Playwright 下打不开窗口（已提交的版本也一样，空白 Electron 正常），解锁后补跑 `smoke-site-list-desktop`、`smoke-site-versions-desktop`、`smoke-site-share-desktop`。
