# 编程任务：和 Codex、Claude Code 对照

参照：本机的 Codex CLI 0.155.0（`codex`，和编程任务底层用的是同一个 Codex）、Claude Code 2.1.277（`claude`）、Claude 桌面版的 Code 页。没有安装 Codex 桌面版，所以 Codex 这边以 CLI 和 app-server 协议为准。

编程任务的底层已经是 Codex 本身（`codex app-server`，同一套沙箱、审批、`apply_patch`、计划、子 agent），权限档位也逐一对应 Codex 的沙箱与审批策略。**不一样的是产品这一层的逻辑**：一轮工作怎么呈现、人在过程中能做什么、事后怎么看改动和撤回。

## 两者共同的逻辑（本产品应当一样）

1. **一轮工作是一条按时间排的流水**：人的话 → Agent 的说明 → 它读了什么、跑了什么命令（带输出）、改了哪个文件（红绿 diff、+N −M）→ 更新计划 → 继续说明 → 最终回答。每一步出现在它发生的位置。
   - Codex：`• Explored └ Read x · Search y`、`• Ran npm test`、`• Edited a.js (+3 -1)`、`• Updated Plan`、结尾 `Worked for 45s`。
   - Claude Code：`⏺ Read(x)`、`⏺ Bash(npm test)`、`⏺ Update(a.js) ⎿ 3 additions, 1 removal` 带 diff、`⏺ Update Todos`。
2. **浏览代码的命令归成一组**，不逐条罗列原始命令；命令显示它本来的样子，不带 `/bin/zsh -lc` 包装。
3. **审批就在那一步上问**：允许 / 允许且本轮不再问同类 / 拒绝并告诉它该怎么做。
4. **过程中可以继续说话**（插话，下一步就看到），可以随时停止。
5. **斜杠命令**：`/compact`、`/undo`（Codex）或 rewind（Claude Code）、`/review`、`/diff`、`/init`、`/new`、`/approvals`（Codex）或 `/permissions`（Claude Code）、`/model`、`/status`。
6. **`@` 引用项目里的文件**。
7. **计划模式**（Claude Code）：先只读地出计划，人认可后直接按计划执行，不用重新描述一遍。
8. **看改动**：`/diff`，桌面版有改动面板，列出工作目录里所有改过的文件和 diff。
9. **撤回会恢复代码**：Codex `/undo` 用每轮之前的快照恢复文件；Claude Code 的 rewind 可以同时恢复代码和对话。
10. **看得到上下文还剩多少**：Codex 底部一直显示「58% context left」，`/status` 写「Context window: 58% left (116K used / 486K)」；Claude Code 快满时提示剩余百分比。
11. **↑ 调出之前发过的话**：两者都有，输入框空着时按 ↑ 往回翻、↓ 往回走。
12. **回到更早的某一轮**：Claude Code 的 rewind（Esc Esc 或 `/rewind`）选一条之前的消息，可以只退对话、只退代码或两者都退；Codex 的 Esc Esc 回溯到之前的某条消息。两者都把那条消息放回输入框，改了再发。
13. **粘贴图片**：两者都能把截图粘进输入框，随消息发给模型（Codex 的 `localImage`，Claude Code 的图片附件）。
14. **项目自己的斜杠命令**：Claude Code 读项目里的 `.claude/commands/*.md`，Codex 读自定义 prompts；`/名字 参数` 把那段文字（`$ARGUMENTS`、`$1`…`$9` 换成参数）当消息发出去。

**2026-09-22 交接核对结果**：交接时指出的 C2、C4、C5、C7、C15 差距分别由 U01、U09、U10 和 U14 收口；自动证据见 `docs/evidence/task-ui/acceptance.md`。肯定确认和真实外部副作用仍只按 M01–M10 计人工验收，不能由这些自动结果替代。

真实环境里发现的：
- **原来的「回退一轮」在锁定的 Codex 0.155 上本来就用不了**：Codex 拒绝 `thread/rollback`（「paginated threads do not support thread/rollback」），这个接口也已标为即将移除。以前的测试都用假客户端，没发现。现在用 `thread/fork` + `beforeTurnId`，这需要在初始化时声明 `experimentalApi`，只有撤回用的那个短期进程声明。
- **同一个消息 ID 跨轮复用会覆盖上一轮的回答**：假模型每轮都用 `msg_fixture`，第二轮的回答把第一轮的改掉了。真实上游未必每轮都给新 ID，所以按 ID 找消息只在当前这一轮里找。
- **撤回原来还会清空所有轮次的执行记录，而且遇到插话只切掉插话那一段**：现在只去掉被撤回那几轮的记录，并且整轮撤回。
- **模型把补丁当成一个独立工具来调**（真实模型验证，`docs/evidence/coding-live.txt`）：MiniMax-M3 调了一个名为 `apply_patch` 的函数，Codex 回「unsupported call」，模型就用 `printf` 重写文件，改动在对话里成了一条看不出内容的命令。Codex 和 Claude Code 能显示 diff，是因为改文件走的是结构化编辑；所以网关把这种调用改写成 Codex 认的 `exec_command` + `apply_patch` 定界符（`.50`，`apply-patch-call.js`），补齐缺的 `*** Begin Patch`。
- **输入 `/review` 回车什么也没发出去**（`.51`）：斜杠命令在表单的 submit 事件里再调 `requestSubmit()`，浏览器派发 submit 时会忽略再次提交。改为下一个任务里提交。
- **结尾统计和「查看改动」对不上**（`.52`）：结尾把每次补丁的 +/− 加起来，同一个文件补几次就算几次（真实任务里 +127 −5，git 看到的是 +75 −7）。现在用 Codex 自己算的这一轮净改动（`turn/diff/updated`），只认这个任务自己的会话；Codex 标为失败的改动显示「未应用」。
- **模型看不懂补丁里 `@@` 那一行**（`.53`）：它以为 `@@` 后面那一行会被替换，把新的函数头写成 `+` 行，结果旧函数头留着、多出一个；又发了只有上下文的补丁想改回来。这些补丁本身都合法，Codex 都回 `Success`，只是意思和模型想的不一样；模型于是认定补丁工具失灵，改用 `rm` 再整个新建。本机 codex 0.155.0 实测：`@@` 那一行只定位，把它写成 `-` 行去改会报「Failed to find expected lines」，要用光秃的 `@@` 才能改它；只有上下文的块什么也不改，却照样回 `Success` 并列出文件。编程说明据此补了两句。

- **`/review` 走 Codex 审查模式后，真实模型暴露了三个问题**（`.63`，`docs/evidence/coding-complex-live.txt` 第四节）：
  - 单独撤回审查那一轮失败：Codex 对 `review/start` 回的 turn id 拒绝分叉（「does not have a persisted start boundary」），它真正存下的是审查开始时 `turn/started` 里的另一个 id。现在审查轮记这个 id，实测从它之前分叉正好只留前面的轮。
  - 审查结果只剩最后一截 JSON：MiniMax-M3 有时把一个回答拆成很多条消息发出（实测一次 13 条、一次 48 条，每条 80–170 字），Codex 只拿最后一条当审查结果，解析不了就原样显示那一截。网关现在把紧挨着的同类消息合回一条（`message-coalesce.js`）；为了不让「后面还要想一会儿才调用工具」的消息迟迟不结束，只等 300 毫秒。
  - 审查在高推理强度下想过头：一次在第 13 个请求里把 16,384 个输出 token 全用在逐条对照审查准则上，没写出答案；另一次跑了近 10 分钟。审查那一轮改用中等强度（实测 Codex 的审查沿用会话的强度），普通轮不变。

- **「还不是 Git 仓库」这个标签两个对标都没有**（`.65`）：本机 codex 0.155.0 实测，`codex exec` 在非 Git 目录里直接拒绝执行（`Not inside a trusted directory and --skip-git-repo-check was not specified`），也就是说 Codex 只在第一次信任这个目录时问一次，之后再不提；Claude Code 从头到尾不提。我们原来是第三种做法：每次打开项目列表都挂一个标签和一个按钮，既不拦人也不闭嘴。现在按「需要的时候才说」改：标签和常驻按钮都去掉，按钮挪进「查看改动」——那里才是没有基准真正挡路的地方。

看过、决定不改的：
- **思考过程不显示**：MiniMax-M3 只给原始思考、不给摘要（真实任务的 Codex 会话记录里 17 条 reasoning，summary 全是空的）。Codex 默认不显示原始思考（`show_raw_agent_reasoning` 默认 false，按锁定的提交核对过），所以编程任务里也不显示；模型哪天给了摘要，再照 Codex 显示摘要。
