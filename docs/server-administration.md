# 服务端管理系统 · 设计

> 状态：R1、R2、R3 已实现；R4 的第一版（只记不拦）已实现，降级本身未实现。每一节末尾写明「已经是什么」和「还不是什么」。

## 0. 这份设计要解决的三件事

1. **私有化「放行所有」太宽。** 站点监听器是这个部署里唯一对网络开放的东西；`IDOU_SITES_ANONYMOUS=1` 之后任何能连到这个端口的人都能打开免登录的站点。需要一层网段白名单，由服务端控制。
2. **模型对所有人一样。** 服务端列出有哪些模型，每个人自己挑一个，没有「谁能看见哪些」。
3. **没有额度这回事。** 只有每会话的频率限制（`requestsPerMinute` / `maxConcurrent`）和云盘字节数配额（`DriveBudget`）。模型用量不记账，也没人能看。

外加一件贯穿的：**现在没有任何管理面**。所有策略都是环境变量 + 重启，运维只能改文件。

## 1. 现状（写下来，免得设计和现实打架）

| 已经有 | 在哪 | 形态 |
| --- | --- | --- |
| 会话与 scope | `sessions.js` | `audience` + `scopes`，**没有角色**，没有「管理员」 |
| 模型路由 | `model-gateway.js` | `models[]`，按 `body.model` 路由；每会话频率/并发限流 |
| 模型选择 | `model-choice.js` | 服务端列出，人自己挑，选择存服务端 |
| 云盘配额 | `drive-budget.js` | SQLite，按租户 `maxBytes`，**有超限拒绝** |
| 审计 | 各服务 `audit()` | 写 stderr 的 JSON 行，**没有留存、没有检索** |
| 对外监听 | `site-server.js` | 唯一绑非回环的东西；飞书访客登录 + cookie |
| 其余一切 | `bin/server.js` | **只绑 127.0.0.1** |

两条由此而来的判断：

- **网段白名单只需要加在站点监听器上。** 别处加是装样子——它们根本不接受网络连接。
- **管理台如果做成网页，它就是这个部署第二个对外的鉴权面。** 所以它必须在白名单后面，而不是白名单之外。

## 2. 决定（用户已选，含代价）

| 岔路 | 选择 | 代价，如实说 |
| --- | --- | --- |
| 管理台在哪 | **独立网页控制台** | 多一个对外鉴权面。服务器上没装桌面应用也能管，但登录、会话、CSRF 全要自己做对 |
| 谁是管理员 | **跟飞书的群/部门成员** | 不在两边维护名单，飞书里改了立刻生效；代价是每次鉴权都要问飞书，且**依赖一个 scope**（见 §4.1） |
| 额度超了 | **软上限：降级不拒绝** | 不会把人锁在外面；代价是「超额」不再是一道硬墙，成本上限靠降级后的便宜模型兜 |

## 3. R1 · 网段白名单（已实现）

**在哪：** 站点监听器接受连接的第一步，早于路由、早于 cookie、早于飞书。一个不在名单里的地址连页面长什么样都不该知道。

**配什么：** `IDOU_SITES_ALLOW`，逗号分隔的 CIDR，IPv4 和 IPv6 都收。留空＝不限制（和今天一样）。

```
IDOU_SITES_ALLOW=10.0.0.0/8,192.168.0.0/16,fd00::/8
```

**几条刻意的规矩：**

- **回环永远放行**，无论名单怎么写。否则运维在服务器上 `curl` 自己都不通，而这是排查时第一件要做的事。
- **只认 socket 上的对端地址**，不认 `X-Forwarded-For`。转发头是客户端能随手写的字符串；信它等于没有白名单。反向代理后面的部署要么让代理做白名单，要么把代理放进名单——这一点写在部署文件里，不留给人猜。
- **拒绝是 403 加一句话，不是静默丢弃。** 悄悄丢包会让运维查半天网络。
- **解析在启动时做**，一条写错的 CIDR 让服务端起不来，而不是运行时变成「谁都放行」。

**不是什么：** 这不是身份认证。白名单只回答「这个地址能不能连」，谁能打开哪个站点仍然由 `site-access.js` 按飞书身份逐请求判定。两者叠加，不互相替代。

## 4. R2 · 管理员与网页控制台（已实现）

### 4.1 管理员是谁

配置里写一个飞书**群** id（`IDOU_ADMIN_CHAT`）：在这个群里的人就是管理员。

- **为什么是群不是部门**：部门是 HR 结构，不是权限组；而且自查身份接口只返回基本资料，**没有 `department_ids`**（2026-09-21 实测），要读部门得另一个 scope，产品应用未必有。群成员用 `im/v1/chats/{chat_id}/members` 就能读，机器人身份可调。
  > 实测（9-21）：机器人能调 IM 的读接口，但**它不在任何群里**——所以「把应用机器人拉进管理员群」是一个真实的前置步骤。`admin-chat-members.js` 把「缺权限」（99991672/99991679）和「机器人不在群里」（230002/232002）**分开报**，因为不分开两者都会变成一个空列表，而空列表和「这个群真的没人」长得一模一样。
- **名单缓存 60 秒**。飞书里踢人要能很快生效，但每个请求都去问飞书会把管理台变成飞书的压测工具。
- **问不到飞书时拒绝，不是放行**。名单读不到就当没有管理员——一个鉴权系统在依赖不可用时必须失败关闭。
- **根管理员兜底**：`IDOU_ADMIN_USERS` 可以写几个 open_id，用于「群被删了」这种把自己锁在外面的情况。它是逃生口，不是日常机制。

### 4.2 控制台在哪

**一个自己的监听器，一个自己的地址**（`0.1.0-20260929.258` 起）：

```
IDOU_ADMIN_URL=https://admin.example.com   # 管理员打开管理台用的地址，必须和 IDOU_SITES_URL 不同源（换主机名或端口）
IDOU_ADMIN_PORT=3045                       # 本机监听端口，和文档网站一样绑在 IDOU_SITES_BIND 上
```

原来它是站点监听器上的 `/admin` 一族路由。改的原因是 9-27 安全审查：发布的网页本身就是作者写的脚本，和管理台同源时，管理员一打开这个网页，页面就能用管理员的 cookie 读 `/admin/state.json`——每个人的用量、全部站点、审计记录。现在：

- 两个监听器互不提供对方的路由：站点上的 `/admin` 是 404，管理台上只有 `/admin`、`/admin/state.json` 和登录。
- 管理台有自己的 cookie（`idou_admin`），用站点密钥派生出的另一把密钥签名：cookie 不按端口区分，网页也能按名字写 cookie，所以两边都不认对方签的。
- 地址白名单（`IDOU_SITES_ALLOW`）对两个监听器都生效；反向代理后面要在代理上限制来源（见 §3）。
- 登录走同一个飞书应用，所以管理台的回调地址 `<IDOU_ADMIN_URL>/_auth/callback` 也要加进飞书开放平台的「重定向 URL」。启动日志会把两个回调地址都写出来。
- 设了管理员但没有 `IDOU_ADMIN_URL`，管理台不开，启动日志说明原因。

**它和站点不共用会话判定**：cookie 只说「你是谁」，管理台每次请求都要再问一次「你还在那个群里吗」。

### 4.3 控制台看得见什么（第一版只读）

已经有的：

- **这个部署允许什么**：免登录、网段白名单、无人值守、沙箱模式。免登录开着又没有白名单时直接标红。
- **模型**：配了哪些、**现在能不能答**（来自 `model-health` 的真实请求结果，不是页面去 ping）、默认是哪个
- **模型可见性**：策略里的每条规则和它的优先级（R3）
- **站点**：发布了哪些、谁能打开（用分享面板的同一套词）、接没接表格、多大
- **管理员**：来源和人数——**从不显示是谁**，一个列出全部管理员的页面是值得偷的页面
- **审计**：最近 200 条事件（内存里，重启即清空；长期留存收集 stderr 上的 JSON 行）

还没有的：**谁在用、用了多少**——那是 R4 的记账，页面上明着列在「还没有的」里。

**第一版只读是刻意的。** 一个能改策略的管理台，如果它的数字是错的，改出来的就是错的。先让数字被看见、被核对。

**它不读对话内容**，靠的是这个文件根本拿不到那些数据，不是页面选择不渲染。

## 5. R3 · 模型可见性（已实现）

**策略的形状**：一条规则说「谁」能看见「哪些模型」。

```jsonc
{ "who": { "kind": "chat", "id": "oc_…" },  // 或 { "kind": "user", "id": "ou_…" }，或 { "kind": "everyone" }
  "models": ["MiniMax-M3", "GLM-5.3"] }     // 顺序即默认
```

**判定顺序**：具体的盖过宽泛的（user > chat > everyone）。匹配不到任何规则时，看得见的是空集还是全集，由 `IDOU_MODEL_DEFAULT_VISIBLE` 决定，**默认全集**——否则升级这一版会让所有人一夜之间没有模型可用。

**两处必须一起改，否则是假的**：

1. `model-choice.js` 的列表按人过滤（这是人看得见的那一面）。
2. **`model-gateway.js` 按人拒绝**（这是真正的那一面）。只改列表等于把门锁挂在门上但没锁——`body.model` 是客户端发的，沙箱里的 agent 可以直接指定一个没授权的模型。

已有的 `effective` 逻辑（选择失效自动切换）天然兼容：一个人被收走某个模型，他的选择就不再 offered，自动落回服务端顺序里第一个他看得见且健康的。

### 实现之后补上的一条：降级也要判

写的时候才发现还有**第三处**。网关在一个模型答不了时会按 `model-health` 换下一个——而 `health.route()` 和 `health.next()` **只看健康，不看授权**。也就是说上面那条拒绝「只在一切正常的时候成立」：真正想用没授权模型的人，只要等那个授权的模型挂一次，就会被降级进去。

所以每一个候选都重新判一次：第一个候选不合规就在允许集合里另找一个；降级链上遇到不合规的**跳过而不是停下**（后面可能还有一个他能用的）。

配置：`IDOU_MODEL_POLICY_FILE`（一个 JSON 文件）、`IDOU_MODEL_DEFAULT_VISIBLE`（`all` 默认 / `none`）。策略在**启动时**按服务端真实提供的模型校验，写了个不存在的模型名服务端直接起不来——一条作者信了假话的规则，留到请求时才炸只会让人更难查。

**还不是什么**：管理台只能看策略，不能改（改动仍然是编辑文件 + 重启）。按群的规则需要应用机器人在那个群里，读不到时该规则**不命中**，人落到下一条规则上——所以飞书不可达时发生的事，等于这个部署本来就声明的「没有规则命中的人怎么办」，而不是这里另外发明的一个答案。

## 6. R4 · 用量记账与软上限降级（记账已实现，降级未实现）

### 6.1 记账

模型网关本来就代理每一次响应，`response.completed` 里带 `usage`。按「人 + 模型 + 天」累加，落 SQLite（和 `drive-budget.js` 同一套做法：一个文件、一张表、写入即落盘）。

**记的是什么**：input / output / total token 数、请求数、被降级的次数。
**不记什么**：提示词、回答、工具参数。用量表是给运维看成本的，不是第二份对话记录。

### 6.2 软上限怎么降级

一条规则给一个人（或群）一个每日 token 上限和一个**降级目标**：

```jsonc
{ "who": {…}, "dailyTokens": 2000000, "downgradeTo": "GLM-5.3", "concurrency": 2 }
```

超过上限之后，这一天里：

- 请求被**改写到 `downgradeTo`**（而不是拒绝），并在响应里带一个标记，客户端据此在界面上说明「今天的额度用完了，现在用的是 X」。
- 并发上限收到 `concurrency`。
- **没有 `downgradeTo` 时才拒绝**，并且拒绝语要说清是额度不是故障。

**必须说清的一条**：降级是**改变了这个人拿到的东西**。所以它一定要在界面上说出来——一个人以为自己在用 A、实际在用 B，比被拒绝更糟。

### 6.3 上线顺序（按 [[rollback-safe-data-changes]]）

1. **`.N` 只记不拦** ← **现在在这一步**。记账上线（`IDOU_MODEL_USAGE_FILE`，不设就是数据目录里的 `model-usage.sqlite`），管理台看得见数字，没有任何拦截或降级。
2. 核对一周：数字和账单对得上吗？有没有人被错记？
3. **`.N+1` 才打开降级**，且带一个总开关可以立刻关掉。

### 记账已经是什么

- 在网关代理响应的路上顺手读到：流式从 `response.completed` 那一帧读，非流式从 JSON 体读。**一个字节都不改**——冒烟里断言了流出去的内容和上游发来的逐字节相同。
- **只在上游真的答了之后才记**（HTTP 200 且有 served 模型）。被拒的请求没花任何成本，记它等于虚报每个人的用量。
- 按「人 + 模型 + 天（UTC）」累加，落 SQLite。人以 tenant+id 的哈希做主键。
- `total` 缺失或小于分项时自己相加——各家上游对 `total` 给不给、怎么给并不一致，宁可算出来也不要留一个没人发现的缺口。
- **表里没有提示词、回答、工具参数那几列。** 这是机制，不是界面选择：管理台拿不到它装不下的东西。单测直接断言了列名集合。

### 还不是什么

- **没有任何拦截或降级。** 额度规则的形状设计好了（上面 §6.2），但这一版连规则都还没读。管理台上那一段明写着「这一版只记不拦」。
- 按 token 记不按钱记（见 §8）。

## 7. 安全边界（一次说完）

- **白名单不是认证。** 见 §3。
- **管理台是第二个对外鉴权面。** 它在白名单后面；它的每个请求都重新判定管理员身份；它不接受任何 `Origin` 不是自己的写请求。
- **管理台不读对话内容。** 它看得见谁用了多少、什么时候、哪个模型；看不见问了什么。这条要用代码保证（用量表里没有那些列），不是靠界面不显示。
- **改策略是写操作，要有审计**：谁、什么时候、把什么改成了什么。审计记录在控制台里能查，且**管理员不能删自己的审计**。
- **失败关闭**：管理员名单读不到 → 没有人是管理员；白名单解析不了 → 服务端不启动；额度库读不到 → 按「没有额度限制」放行**并告警**（这一条反过来，因为把所有人挡在外面比暂时不限额更糟）。

## 8. 诚实的边界

- 这套东西管的是**这一个部署**。多部署要各管各的，没有跨部署的总控。
- **额度按 token 记，不是按钱记。** 换算成钱要知道各家当时的价目，那是随时会变的外部事实，写死在这里迟早是错的。管理台显示 token，成本核算在外面做。
- **降级依赖多模型路由是通的**（`IDOU_MODEL_PROVIDERS` 配了不止一个）。只配了一个模型的部署，软上限只能变成硬上限或不限，管理台要如实这么说，而不是给一个点了没用的开关。
- 管理台**不管飞书**。踢人、建群、改部门都在飞书里做，这边只读。
