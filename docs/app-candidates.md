# 自建应用平台：待审版本目录与云盘归档

已实现的是发布前版本留存与目录，不是应用托管服务。路径为 **编程任务 → 浏览器预览 → 应用版本**。不依赖妙搭，不新增一级导航；每个编程任务对应一个应用标识。

现已接入[企业清单审核](app-reviews.md)：单独配置审核人，查看其他作者的文件清单并通过/退回，结论按版本持久化，作者刷新可见。只审核元数据声明，不读取源码，不是发布授权。

## 当前可用流程

1. 在独立静态产物目录准备 HTML 入口，例如 `dist/index.html`。先在现有浏览器预览中验收交互，再进入「应用版本」。任务运行中不能提交或撤回版本。
2. 客户端收集入口所在目录及子目录的静态文件，生成按路径排序的文件名、字节数、SHA-256 清单。版本哈希覆盖整个清单、入口和固定运行策略，不依赖不可靠的“最近构建成功”标记。
3. 原生确认框显示服务端、产物目录、版本哈希、文件列表和元数据上传范围。取消不保存版本，也不发出提交请求。确认后再次读取目录；内容、目录或账号变化时拒绝提交。
4. 客户端先把确认过的实际字节作为不可覆盖的 JSON/base64 包保存到账号数据目录 `application-candidates/<digest>.json`，然后只提交清单。已有同名包不一致或本地写入失败时，不提交、不覆盖。文件按 0600 保存并同步到磁盘；源码包不会发送给控制服务。
5. 服务端目录用 SQLite 事务持久化待审记录。相同应用/版本重复提交返回已有记录；响应丢失后刷新目录即可核查，不自动重发。客户端和目录重启不丢失已保存记录。
6. 可以原生确认撤回版本，保留历史和本机包，不删除文件。相同版本再提交不会恢复已撤回状态；修改内容后生成新版本。撤回确认绑定原账号和服务端连接。
7. 填写企业配置的云盘文件夹，在版本卡片点击「归档到飞书云盘」。客户端读取**已保存版本包**，逐文件核对路径、规范 base64、长度、哈希与清单哈希，而非读取最新工作目录。拒绝不规范 JSON、篡改、链接、不安全缓存权限及超过 15 MiB 的包。
8. 原生确认说明完整源码/资源上传范围、目标文件夹、CLI 企业、实际包大小和包 SHA-256。取消不建立归档记录、不占预算、不上传；确认会上传一个新 `.app.json` 文件，既不覆盖旧文件，也不调整权限。云盘中的文件夹可访问者可能读取包内容，需先确认无敏感信息。
9. 服务端为每个应用版本持久化唯一上传 ID。实际包字节数（含 JSON/base64 开销）复用媒体的企业云盘预算。客户端取得应用目录的一次性许可和预算的一次性许可后，才调用 CLI；两份账本不组成分布式事务，任何不确定窗口保守停下，不重新分配上传 ID。
10. CLI 回执中的文件 token 记入目录后，只读列取原文件夹，核对精确 token、文件名、类型与位置，回报预算与目录状态。已有回执可在客户端/服务端重启后点击「重新核验云盘目录」，不依赖本机源包、不重复上传。成功提示为「已归档 · 客户端已核验目录」，**尚未验证远端内容哈希，不是部署成功**。
11. 点击「取回并校验版本包」，以当前 CLI 用户重新读取精确文件，而不是使用本机旧包。下载前后核对身份和原目录位置，再核对规范包、逐文件哈希、清单哈希、实际总包大小及归档包 SHA-256。校验后重新确认应用目录记录/账号未变化，把规范包保存回本机版本缓存；原有坏包不自动覆盖。界面显示本次校验时间，不向控制服务声称独立验证成功，不执行、解压到工作目录或部署代码。
12. 点击「校验并预览归档版本」，每次重新从云盘读取并完成上述校验，然后只使用这份包的内存字节打开原生浏览器。刷新同样重新下载，不读取当前工作目录或本地缓存；失败时关闭旧页面，不用旧内容替代。本步骤不保存缓存、不再次上传或记费。标题标记版本号与到期时间；返回按钮回到应用版本列表。

### 归档预览边界

原生临时 HTTP 服务仅监听 loopback，使用随机路径能力地址，只服务清单内文件，拒绝其他 Host、跨源 Origin、写请求与未知路径；无解压和工作目录访问。每个页面使用非持久 Electron partition、sandbox/context isolation，关闭 Node 集成且没有应用 preload/IPC。请求拦截限定到这份包，CSP 禁止框架、Worker、表单提交和对象加载；弹窗、下载、权限请求被拒绝。页面允许包内 JavaScript 与内联脚本，因此**不是代码安全审查通过**。

产物需要使用包内相对资源路径；根绝对路径、外部 CDN/API、服务端逻辑及依赖在线服务的 SPA 暂不支持。当前预览不是任意开发服务器代理。

授权快照最长 5 分钟且不超过本机父会话到期时间；每次打开/刷新重新核验当前目录、CLI 身份与服务端授权。到期、关闭、任务/标签切换、账号切换、应用界面重载时销毁页面并关闭临时服务；迟到的下载不能重新挂载页面。关闭绕过页面的 `beforeunload` 阻挠，并等待实际 WebContents 销毁，见 [Electron WebContents.close](https://www.electronjs.org/docs/latest/api/web-contents#contentscloseopts)。加载等待上限 15 秒。

已打开页面不持续轮询远端 ACL/父会话撤销，撤权传播最多受剩余预览有效期约束；不能把这个快照当作持续授权。浏览器/CSP 限制**不是 OS 级全协议网络隔离或 CPU/内存硬配额**，不声称阻断所有 DNS/WebRTC 等旁路，不适合直接托管恶意多租户程序。本地能力 URL 也不是针对同一 OS 用户的强安全边界。企业发布仍需独立隔离运行节点和访问校验。

右侧保留任务对话，但不自动把当前工作文件冒充归档上下文，也不提供直接修改归档包的能力。修改工作目录、重新构建并提交会生成新版本；预览不会让已撤回版本重新待审或部署。

### 取回安全与资源边界

CLI 固定使用 `drive +download --file-token … --output payload.bin --as user --format json`，目标在新建私有临时目录，不使用云端返回的输出路径、不覆盖用户文件。没有已记录 file token 的不确定上传不能通过文件名取回。CLI 下载失败、目标丢失/移动、身份变化、大小超限、内容篡改或目录记录在读取期间变化时拒绝保存；即使旧本机包存在，也不回退成“本次成功”。

`lark-cli 1.0.78` 的下载命令没有大小上限参数。应用对指定输出文件每 25ms 进行大小/类型监测，超限立即终止子进程；下载总超时 60 秒，忽略 SIGTERM 的进程在 500ms 后升级终止。等待进程与输出管道关闭后才清理临时目录，避免仍写文件的进程与清理竞争。终态读取同样有严格字节上限，不相信 CLI 的成功包络就认定文件正确。

**轮询监测不是 OS 硬磁盘配额**：CLI 可能在两次检查间写入超过上限，内存读取上限不等于磁盘使用硬上限。真实大文件/磁盘耗尽/应用强制退出后的临时目录治理、Windows/Linux 终止与权限语义仍需平台验收。当前测试证明指定直接子进程终止，不是任意子进程树沙箱。

本次客户端读取校验只证明取回字节与原来确认的清单/归档包相符，不证明代码可信或安全，不保证后续云盘内容/权限不再变化，也不能充当发布许可。后续预览或发布消费者必须绑定这份已校验版本并重新核验自己的授权；发布节点的独立下载验证仍未实现。

## 归档失败与恢复

- `prepared`：上传意图已保存，尚未取得应用上传许可。目标/身份/包/预算策略不变时可重新明确确认；已经占用但未成功推进的预算仍保留，可能需要管理员核查。
- `uploading`：应用许可已经发出；不能断定 CLI 已执行或文件不存在。无文件 token 时只提示原文件夹人工核查，不按同名文件冒领、不自动重传。不要另建任务规避此限制。
- `recorded`：服务端已收到文件 token，目录核验或预算回报尚未完成。可以只做核验/元数据回报恢复，不上传文件。
- `listed`：客户端曾在精确目标目录核验到文件。这个状态是客户端报告，不是控制服务独立下载/验哈希的证据，也不保证文件以后不被移动、删除或修改。

撤回发生在应用许可发出前时拒绝上传；发出后无法原子撤销在途 CLI 操作。已经在途的回执仍可记入目录，但不会把已撤回版本恢复成待审版本，更不会部署。撤回不删除云盘文件、不返还预算。应用与预算数据库必须一致备份/恢复；恢复旧快照可能丢失去重历史，当前未提供安全自动恢复和账本对账流程。

## 管理员配置

设置服务端环境变量 `IDOU_APPS_CONFIG_FILE`，指向绝对路径 JSON 文件，再启动既有 `node bin/server.js --feishu`。配置示例（替换示例标识与路径）：

```json
{
  "schemaVersion": 1,
  "databaseFile": "/srv/idou-private/apps/catalog.sqlite",
  "tenants": [
    {
      "authProvider": "feishu",
      "tenantId": "your_verified_tenant_key",
      "appId": "cli_your_product_app",
      "publishers": ["authorized_product_user_open_id"]
    }
  ]
}
```

`publishers` 使用本产品 OAuth 应用验证过的用户标识，不能拿其他飞书 App 的 `open_id` 直接替代。此名单授权的是管理自己的版本清单及归档元数据，不是部署权限。开发模式需明确配置 `authProvider: "development"`、`tenantId: "development"`、`appId: null`、`publishers: ["local-developer"]`，并以 `--dev` 启动；不默认给所有开发用户开通目录。

归档还必须配置 `IDOU_DRIVE_CONFIG_FILE`，参见 [云盘预算配置](drive-budget.md)。应用归档和媒体共享同一租户账本及目标文件夹限制，不另建不受管控的存储服务。企业登录到 CLI 的身份关联仍未完成，企业业务操作继续关闭；目前通过开发连接和隔离替身验证流程，没有绕过该门禁。

数据库位于私有目录：POSIX 目录 0700、文件 0600，拒绝符号链接目录和不安全权限；Windows 需另配等效 ACL。使用独立的应用目录数据库路径，不与预算账本或其他服务共用文件。当前数据库版本为 `user_version=3`；从 1/2 增量保留候选和归档，增加审核记录。旧二进制不能直接打开版本 3，见[迁移说明](app-reviews.md)。损坏或未知版本数据库启动失败，不静默重置。需要保留数据库及 WAL 的一致备份；生产迁移、备份恢复、故障切换仍需部署验收。

## 身份与内容边界

- 单独的 `app-catalog` 短期凭据，最长 5 分钟且不超过父会话。模型、媒体、预算、MCP 或技能凭据不能替代它；父会话撤销立即失效。授权按认证来源、租户、产品 App ID 和发布者白名单检查。
- 创建者可查看及撤回自己的应用记录；企业明确配置的审核人可通过独立入口查看其他作者的版本清单，但不能读取归档详情、冒领应用、修改或撤回版本。企业共享运行目录和协作开发权限尚未接入。
- 控制服务只保存标题、文件路径/哈希/大小、身份哈希、状态、时间、审核说明及结论，以及归档 ID/目标/包哈希/大小/文件 token，不接受源码正文、媒体字节、任意构建命令或执行代码。所有响应固定 `deployed:false`，版本仍只有 `submitted` / `withdrawn` 状态，审核与归档状态独立保存。
- 清单和归档回执都是客户端声明，服务端并没有独立拿到源码包、执行构建或验证包存在。**目录记录不能作为部署许可或可信远端产物的证明。** 本机规范包在显式确认后成为云盘上传对象，但发布节点使用前仍需独立获取并校验。
- 新增 `archive-prepare` / `archive-dispatch` / `archive-receipt` / `archive-verify` 原生 POST 路由，沿用 owner 检查及 `app-catalog` audience；不接受模型 token 或带浏览器 Origin 的调用。JSON API 不接收包字节。归档内容与大小声明不能防止恶意修改客户端绕过记账；当前预算不是飞书总容量强制限额。

## 限制与后续工作

支持 HTML/HTM、CSS、JS/MJS、JSON、PNG/JPEG/WebP/SVG、WOFF2；最多 128 个文件、每文件 2 MiB、合计 10 MiB，目录最多 8 层，每目录最多 256 项。隐藏文件、`node_modules` 和 `vendor` 不收集；其他不支持的文件或符号链接直接拒绝，不生成伪完整包。读取使用有界缓冲区。不会安装依赖、打包、执行源码或扫描出全部秘密；用户应提供已构建且可独立预览的静态目录。当前网络策略固定 `none`，不是对代码中所有网络意图的静态证明。

本机缓存每账号目录最多 30 包，服务端每应用最多 30 个版本、全局最多 10,000 条；达到限制后拒绝新增，暂不自动删除或归档。JSON/base64 会有体积开销。包对同一 OS 用户并非防篡改存储，也不提供文件系统整体原子快照；应用确认约束的是捕获并再次比对过的字节，而不是后续继续修改的活动目录。

待完成：真实企业云盘上传/下载验收、发布节点独立下载/验证、未知上传对账、预算释放、构建队列、依赖锁定、审批与发布撤回策略、隔离运行节点、内网访问身份、健康检查/切换/回滚、后端与业务数据库、共享目录、模板和可视化设计器。未生成任何真实上线地址，也未创建外部云资源。
